# Qualification plan — NOT EXECUTED

**Research output, 2026-10-29. None of these tests has run.** Separate implementation/experiment authorization is required. This plan is not a claim that a browser, fixture, extension, bridge or network listener exists.

## Decision gates

1. **G0 — authority and policy:** answer the five route-selection questions in [SUMMARY.md](SUMMARY.md); record effective policy and supported build tuple. If blocked, report the blocked route without changing policy. No alternate method to evade a denial.
2. **G1 — ownership:** choose owned browser first unless continuity with an existing tab is mandatory. Existing mode must separately authorize tab listing/selection and attachment on a synthetic test profile; never begin with a private production profile.
3. **G2 — transport:** try approved Windows bridge/interop for WSL → Windows. Direct CDP is optional only under approved mirrored loopback. Under NAT, no listener-widening fallback. Remote variant requires approved authenticated transport before browser control.
4. **G3 — supply chain:** all runtime bytes, dependencies, drivers and optional CRX/host identified, licensed, verified and already approved. Missing artifact or incompatible version refuses startup; no acquisition.
5. **G4 — evidence:** run the following matrix on approved synthetic fixtures, retain sanitized observations and hashes. Promote only individually passed capabilities. One successful screenshot is not whole-stack qualification.

## Test fixtures and evidence

A future operator provisions an internal fixture with known DOM and AX labels, two ordinary tabs (A authorized, B unselected), cross-origin iframe, popup, navigation target, a counter button, text field, upload echo hash and deterministic download bytes. A controlled synthetic sign-in demonstrates session continuity without reading cookies or credentials. A separate OS test user supplies a negative identity test if authorized. No production sites or profiles.

Record Windows/WSL/Edge/library/extension/driver versions, effective policy summary, topology, run ID, synthetic target identity, expected/actual outcomes, elapsed time, permitted operations, hashes and cleanup ledger. Do not log private URLs, form secrets, storage, auth headers or unredacted production screenshots. All network monitoring and negative tests require the operator's explicit scope.

## Minimal sequence and stop conditions

First run G0–G3 and A1/T1/O1–O3 on the owned path. If these fail, do not expand to user-session attachment. Then run S1–S4, F1 and R1–R2/C2. Existing mode needs A2–A5 (including attach/teardown test A3b), R3 and C1 as its own qualification. T2/T3 document actual WSL alternatives; T4 and Linux-native repeats are optional follow-on matrices, never inferred from the Windows result.

Stop immediately on unexpected user data, forbidden egress, out-of-scope target access, identity mismatch or unexplained mutation. Preserve minimal sanitized evidence, revoke owned grants and report the failure; do not widen permissions. Do not resume a potentially non-idempotent operation automatically.

The final qualification record must say which route/build/capabilities passed, which failed, what was not run, and which resources remain. This research currently has **zero executed PoC tests**.
