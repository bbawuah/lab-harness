## Boundary and API

Phase 2 owns `src/herdr/interactive.ts`, new `src/herdr/shell.ts`, `tests/herdr-interactive.test.ts`, new `tests/herdr-shell.test.ts`, this contract and `docs/evidence/split/**`. The coordinator alone owns `src/pi/workspace.ts`, `lab`, `scripts/start.ts`, command/help, README, guide, publication and bootstrap integration. Provider, appearance and Relay extensions are outside this work. No product source transfer precedes acceptance of this committed contract.

Keep `runHerdrInteractive(options: HerdrInteractiveOptions): Promise<number>` and its existing fields and return convention. Add `shell?: RegularShell` to those options. Omission means the existing single Pi pane and **no regular shell process**, including bootstrap cleanup; the coordinator will omit it for `--single-pane` and pass it for the normal workspace. `cwd` remains the selected project directory for both leaves, supplied by the trusted caller, never by a model. Keep `environment` as Pi-leaf-only string overrides; do not merge it into the server or client environment.

Freeze the new module's caller-facing interface:

```ts
export type RegularShell = {
  executable: string;                  // captured actual user shell, absolute path
  environment: Record<string, string>; // captured original user environment, present entries only
};
export function buildRegularShell(environment: NodeJS.ProcessEnv): RegularShell;
```

The coordinator calls the builder with the original environment captured before Pi isolation or generated values are applied. The builder copies it in memory; absent values stay absent. It validates an absolute usable `SHELL`, using `/bin/sh` when absent; invalid/non-executable selection fails clearly before launch rather than silently launching another program. It must not read startup files or credentials. The adapter consumes `shell` and `cwd`; no shell configuration or secret is interpolated into shell code. The builder and adapter reject NUL-containing values/arguments. The shell gets the original HOME, PATH, SHELL, locale (`LANG`, `LANGUAGE`, `LC_*`), TMPDIR, XDG variables and ZDOTDIR with their original presence, along with ordinary original environment, except the isolation names below. Native shell startup and job control remain the user's; choose the actual shell before applying leaf environment. Run it interactively with its native normal startup semantics, without forced login, `--norc`, synthetic RC or injected `cd`. Requested cwd is the process starting directory; an RC may intentionally change it afterward.

Herdr leaf `env` accepts only string overrides; it cannot express deletion. Start server and client with `isolatedEnvironment` plus owned session/socket settings only, never Pi overrides or captured original user environment. A shell-leaf owned wrapper may explicitly unset inherited Herdr isolation variables (`HERDR_*` and inherited isolated HOME/PATH/SHELL, locale, TMPDIR, XDG and ZDOTDIR as applicable) before restoring the captured present values and `exec`ing the actual interactive shell. Restore absent entries as absent, not empty. Do not place captured values, generated Pi model key, Relay reference or agent directory in wrapper argv or files. Generated Pi key, Relay reference and agent directory must never reach shell, server or client; test presence and equality in-process with synthetic sentinels without printing real values. Explicit command argv bypasses Herdr native `shell_mode=auto`, whose choice happens before leaf env; the wrapper must preserve intended shell startup semantics rather than relying on that setting. No second AI/runtime or user RC inspection.

## Layout, control and lifetime

`workspace.create` produces a bootstrap tab and shell. Obtain its returned active tab ID (or validate the one returned by `tab.list`), then `layout.apply` with **that `tab_id`** to replace it. Supplying only `workspace_id` creates another tab and leaves a hidden third shell. Validate workspace, tab and distinct pane IDs, and confirm the replaced bootstrap is gone. Apply once, with both leaves using `cwd`:

```json
{"type":"split","direction":"right","ratio":0.6,"first":{"type":"pane","label":"Pi interactive"},"second":{"type":"pane","label":"Terminal"}}
```

Each leaf also carries its own explicit command and string-only env. The returned first leaf identifies Pi and second identifies shell; initial native focus is Pi. Never reapply a layout for resizing, zooming or hiding: it creates processes. Native default controls in pinned Herdr are Ctrl+B followed by h/l/Tab for focus, z for zoom, r for resize mode, x for close, and ? for help. Foreground Ctrl+C goes through the native client to the focused PTY and its foreground process group. Remove the unconditional parent SIGINT forwarding to Pi: if parent receives a signal outside native raw input, resolve the current focused owned pane and send once, or fail safely if focus cannot be established; never send to a stale Pi ID or both panes.

For a narrow terminal, Herdr's 4-by-2 PTY floor is not a usable UI. Candidate policy: below 120 outer columns, use native Pi zoom, preserving the existing shell process; validate the actual threshold visually before treating 120 as final. Only change zoom on threshold crossings; do not steal an existing shell focus on resize. If Pi is not focused when narrowing, defer automatic Pi zoom until it is focused; user focus/zoom controls remain available and a user choice must not cause a focus fight. Widening may undo only zoom owned by this policy, not manual zoom. Bound requests and debounce resize; if focus/zoom ownership cannot be determined, leave native state untouched and surface the limitation. Explicit single-pane is the reliable fallback. No automatic fold, restart or recreated shell.

Shell exit or native shell-pane close leaves Pi and the workspace running. Pi exit, Pi-pane disappearance, workspace close, client detach/exit, parent TERM or HUP, startup failure, or server failure end the owned session and clean up both panes, client, server and sockets. Monitor owned workspace and Pi existence with bounded read-only requests even without an exit file: the client can outlive a closed workspace. An exit file containing 0–255 is authoritative when present and valid; malformed content is an error. Pi disappearance without a valid status, workspace disappearance or detach without Pi status returns nonzero; TERM/HUP return 128 plus signal number. Cleanup errors are reported, not converted to success. Preserve existing raw-mode restoration and bounded startup/cleanup deadlines; close known owned panes/workspace and stop the owned server, then terminate/kill only tracked owned client/server as needed. Verify known owned worker exits and both socket removals; unknown or unverifiable cleanup is a failure. Never discover or signal unrelated processes. Mutating request timeout means outcome unknown: do not blindly retry a layout mutation; stop the owned server and clean up. Parent SIGKILL cannot run cleanup and is explicitly outside the guarantee.

## Acceptance and evidence

Phase 2 must retain the PR 10 readiness marker rendered by the actual native client before input, worker WINCH resize acknowledgement, deadlines and all existing assertions. Do not weaken, globally skip, or replace these checks. Add bounded actual-PTY tests against the verified pinned Herdr binary and harmless Pi stand-in, with independent owned markers and process/socket assertions. Cover:

1. Bootstrap replacement and exactly two leaf processes, Pi initially focused; single-pane creates no regular shell. Keyboard focus h/l/Tab delivers input only to the selected pane, with no accidental input in the other; native zoom and resize preserve both PIDs and worker resize acknowledgement.
2. Narrow/wide transitions and user focus/zoom interaction; record terminal dimensions, actual pane sizes, policy ownership and visible result. Validate the threshold visually at representative widths and heights; no claim of usability based solely on PTY floor. If native behavior cannot satisfy the policy, report the failed criterion and retain explicit single-pane fallback rather than inventing a restart.
3. Synthetic bash and zsh startup fixtures exercise original HOME/PATH/SHELL, locale/TMPDIR/XDG/ZDOTDIR presence and absence, startup behavior, requested cwd and an RC changing cwd. Assert generated synthetic Pi key/Relay/agent values absent from shell/server/client and wrapper argv/files; Pi receives its own overrides. Observe in process without dumping original user values. No real user RC, key files, accounts or model calls.
4. Shell foreground Ctrl+C and job control return to a usable shell without interrupting Pi; shell exit and native close leave Pi responsive. Pi exit, native Pi/workspace close without exit file, client detach, TERM and HUP each terminate owned processes and remove sockets within deadlines. Verify return status, raw terminal restoration, failures and unknown mutation outcomes; assert no unrelated PID is signalled.

Store reproducible evidence under `docs/evidence/split/`: exact source and runtime artifact hashes, OS, terminal size, test commands, synthetic-only setup, result/status and cleanup observations. Capture actual native screen/terminal output; label any browser-rendered text capture as such, and never present a mockup as an implementation. This phase uses a stand-in and does not qualify actual Pi; coordinator separately qualifies pinned Pi without model calls. No full gates, PR watch or merge are part of this phase.

Read-only researcher fixtures are at `$TUI_RESEARCH_WORKTREE/.tmp/layout-research-9d5c607` (the supplied `ignored.tmp` path was absent). Their synthetic native-client results show right/left focus, zoom, shell close with Pi alive, and workspace close with client still alive; one early close/input attempt timed out, and a later fixture succeeded. They created a separate tab and therefore do not establish bootstrap replacement. These are research observations, not phase 2 acceptance evidence. The actual threshold, absence-preserving wrapper transport, startup semantics, cleanup and race behavior remain mandatory implementation proofs.
